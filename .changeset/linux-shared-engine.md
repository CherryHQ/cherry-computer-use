Share one native AT-SPI/X11 engine between the Linux SDK runtime and CLI/MCP, and drop the Linux runtime's Python dependency. The Linux SDK supports secondary actions, `setValue` with range checks and read-back, and `typeText` into the one focused editable field. On X11, pointer clicks, drag, key presses, page scrolling and typing without a focused field require `allowGlobalInput: true`, check that the target window has focus or lies under the pointer, and are released by a guard process if the runtime exits abnormally. On Wayland, key presses, page scrolling and typing without a focused field use a virtual keyboard on Sway and Hyprland (no dialog, any character, bound to the compositor's focused window) and the RemoteDesktop portal elsewhere after `requestPermissions({ ids: ['remoteDesktop'] })`. On Sway and Hyprland, window screenshots come from the compositor (Sway screen copy of the window's region, Hyprland toplevel export) at the window's logical size, and pointer clicks and drag use a virtual pointer that must leave the target focused under the pointer (focus follows the mouse) before any button is pressed; other Wayland compositors report capture and pointer input as unsupported.
