### Execution Context
- Agent: Claude Code
- Runtime: local coding agent

### User request
Fix Cherry Studio PR #21704 review finding: an app bound by a `listApps()` ID fails with `TARGET_UNAVAILABLE` after the host restarts the native runtime between turns.

### Changes
- macOS: derive the app ID from pid, launch date and bundle ID; `resolveApp` accepts such an ID without a prior `listApps()`.
- Windows/Linux: derive the app ID from the driver's existing process key (`pid:start` / AT-SPI bus+path) instead of a per-runtime random ID.
- IDs still expire when the process exits, so a restarted app is never mistaken for the old target.
