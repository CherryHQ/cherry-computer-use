# 后台窗口与任务保护恢复

## 目标与范围

在已接入的后台窗口、虚拟显示器和 Locked Use 上补齐取消、异常退出及物理接管的行为，保留 Cherry SDK v2、独立平台引擎和现有发布流程。

包含：精确窗口与文件弹窗绑定审计；虚拟屏和遮挡状态的恢复；SDK 请求取消与任务退出；Karabiner 独占设备下的接管检测；暗屏保护资源的释放。

不自动执行系统组件安装、锁屏或公开发布。签名组件的安装/升级/卸载及完整锁屏实机验收需要独立证据，不能以单测代替。

## 来源与现状

- 当前基线：`4b9654f`，已经移植后台窗口、PR #114 显示排列逻辑、Locked Use 和 PR #187 暗屏保护。
- [PR #114](https://github.com/iFurySt/open-computer-use/pull/114)：多显示器排列与系统自动搬移窗口。
- [Issue #142](https://github.com/iFurySt/open-computer-use/issues/142)：Karabiner 独占部分 HID 设备；可打开虚拟设备并不自动证明每个物理设备都能触发接管。
- [PR #187](https://github.com/iFurySt/open-computer-use/pull/187)：显示器保活需持续到两层 guard 确认释放。
- 初始实现主要依赖进程内记录和 `atexit`，不可捕获的退出会丢失记录。

## 约束与风险

- 恢复时重新校验 PID、进程实例和窗口归属，不能碰到复用的窗口或另一任务的状态。
- 不在无法确认用户接管检测的情况下启用解锁；不以 CG 全局输入替代定向输入。
- 取消后先排空操作再恢复资源；恢复失败保留依据并返回可诊断错误。
- 所有测试只操作自有 fixture；虚拟屏测试须显式启用并检查既有显示排列不变及结束时恢复，不执行锁屏。
